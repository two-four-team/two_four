# main.c 특이사항

기준 문서: `Plan/고객_요구사항_사양서.pdf` (VBC-SRS-001 v1.0), 참고: `testcase/testcase.xlsx`

## 빌드와 실행

프로젝트 루트에서:

```sh
gcc -std=c99 -Wall -Wextra -I Common -o vehicle_sim \
    Common/main.c HeadLight/headLight.c Wiper/Wiper.c Door/Door.c \
    sensor/sensor.c "Dashboard Warning/ClusterWarning.c"
./vehicle_sim                      # input/input.csv → output/simulation_log_YYYYMMDD_HHMMSS.txt
./vehicle_sim <입력.csv> <로그.txt>  # 경로 지정 (그 파일에 덮어씀)
```

- 실행할 때마다 실행 시각이 들어간 새 로그 파일을 만들기 때문에 이전 로그가 지워지지 않습니다. 같은 초에 다시 실행하면 `_2`, `_3`…이 붙습니다. 로그 머리글에도 실행 시각이 기록됩니다.
- `output` 폴더가 없으면 로그를 만들지 못하고 종료 코드 1로 끝납니다.

Windows (Visual Studio 개발자 명령 프롬프트, 프로젝트 루트에서):

```bat
cl /nologo /W3 /utf-8 /I Common /Fe:vehicle_sim.exe Common\main.c HeadLight\headLight.c ^
   Wiper\Wiper.c Door\Door.c sensor\sensor.c "Dashboard Warning\ClusterWarning.c"
vehicle_sim.exe
```

- `main.c`는 **UTF-8(BOM 포함)**으로 저장되어 있습니다. 한국어 Windows의 MSVC는 BOM이 없는 소스를 CP949로 읽기 때문에, BOM이 없으면 한글 문자열이 깨지거나 C2001 오류가 날 수 있습니다. 편집기에서 저장할 때 BOM을 지우지 마세요. `/utf-8` 옵션을 주면 BOM이 없어도 됩니다.
- MSVC에서만 `_CRT_SECURE_NO_WARNINGS`와 `#pragma execution_character_set("utf-8")`을 적용합니다. 앞의 것은 `fopen` 경고 C4996이 Visual Studio 기본 설정 `/sdl`에서 오류가 되는 것을 막습니다. 뒤의 것은 로그가 CP949가 아니라 UTF-8로 저장되게 합니다.
- Windows에서는 콘솔 출력 코드 페이지를 UTF-8로 바꿔서 한글 안내 메시지가 깨지지 않게 합니다.
- Visual Studio 프로젝트로 실행할 때는 작업 디렉터리를 `two_four` 루트로 설정해야 합니다. 그렇지 않으면 입력과 출력 경로를 인자로 넘기세요.

로그(`output/simulation_log_<실행 시각>.txt`)에는 3.2 출력 6개 항목(전조등, 조도 센서 고장 표시, 와이퍼, 강우 센서 고장 표시, 도어 잠금, 계기판 경고)이 100ms마다 한 행씩 기록됩니다. 직전 행과 출력이 달라진 행은 시각 뒤에 `*`가 붙습니다.

## 1. `ControlDoorLock` 구현 위치

- 처음에는 `vehicle_control.h`에 선언만 있고 구현이 없어서 `main.c`에 임시로 구현했습니다.
- 지금은 `Door/Door.c`로 옮겨졌고, `main.c`의 임시 구현은 지웠습니다. 함수가 한 곳에만 정의되어 있으므로 Windows(MSVC)에서도 중복 정의 오류(LNK2005)가 나지 않습니다.

## 2. testcase.xlsx와 사양서가 맞지 않는 부분 (조치 필요)

- **ControlDoorLock 시트**
  - 잠금 상태를 `DOOR_OPEN`/`DOOR_CLOSED`로 적었는데, 헤더의 타입은 `DOOR_UNLOCKED`/`DOOR_LOCKED`입니다. DL_016을 보면 `DOOR_CLOSED`가 잠김을 뜻합니다.
  - **DL_003~DL_012**(시동 OFF 또는 기어 P)의 기대값이 "현재 상태 유지"로 되어 있습니다. 하지만 사양서 **D2**는 "시동이 꺼져 있거나 기어가 P이면 잠금을 푼다"입니다. 예를 들어 DL_003은 현재 잠김이면 결과가 풀림이어야 합니다.
  - main.c는 사양서를 따릅니다. 테스트케이스를 수정해야 합니다.
- **CheckDoorOpenWhileDriving 시트**: DOW_001은 속도 0일 때 도어 값을 비워 두었습니다. 함수가 속도부터 검사하므로 결과에는 영향이 없습니다.

## 3. 모듈이 맡지 않아 main.c에서 처리한 규칙

| 규칙 | 모듈 상태 | main.c 처리 |
|---|---|---|
| C2 미수신 → 센서 고장 | `sensor.c`는 값 범위만 검사함 | 마지막 수신 후 500ms 이상 지나면 `SENSOR_FAULT`. 처음 값이 오기 전에는 시작 시점부터 셈 |
| C4 차량 상태 수신 중단 | `CheckVehicleStateRx`는 RxState 3개를 받아 합치기만 함 | speed·gear·engine 각각 500ms 미수신을 판정해서 전달 |

| C3 유효한 속도 | `Wiper.c`·`Door.c`는 범위(0~250)만 검사함 | 수신 중단이거나 범위 밖이면 `-1`을 넘겨서 W3·D3·D4 조건이 성립하지 않게 함 |
| C1 L2·L3 시간 조건 | `UpdateLow/HighIlluminanceTime`은 조도 값만 보고 셈 | 시동 ON + 스위치 AUTO + 조도 센서 정상이 아니면 0으로 초기화 |
| C1 L6 시간 조건 | `UpdateWiperActiveTime`은 와이퍼 상태만 봄 | 시동 OFF(C4 포함)이면 0으로 초기화 |

## 4. 사양서에 없어서 정한 가정 (고객 질의 대상)

1. **처음 값이 들어오기 전의 차량 상태**: C5에 맞춰 속도 0, 기어 P, 시동 OFF로 봅니다. 결과는 C5 초기 출력(꺼짐·정지·풀림·경고 없음)과 같습니다.
2. **스위치·도어 초기값**: 조명 스위치 OFF, 와이퍼 스위치 OFF, 도어 4개 닫힘으로 봅니다. 빈 칸이 들어오면 직전 값을 유지합니다. 도어와 스위치는 0.5초 주기 입력이 아니어서 미수신 고장 판정을 하지 않습니다.
3. **"N초 연속"의 경계**: `Update*Time`이 호출할 때마다 +100ms를 더하는 구조라서, 조건이 처음 성립한 행부터 N×10번째 행에서 동작합니다. 예를 들어 L2는 9100ms부터 999 lux이면 10000ms에 켜집니다. 타임스탬프 차이로는 0.9초입니다. 각 행이 100ms 구간을 대표한다고 해석한 것입니다.
4. **0.5초 경계**: 마지막 수신으로부터 정확히 500ms가 된 행에서 고장/수신 중단으로 판정합니다.
5. **수신 중단 중의 도어 잠금 판정**: D1이 먼저 판단되므로 잠금 상태가 유지됩니다. D4 경고는 유효한 속도가 없으므로 꺼집니다.
6. **L6 판단 시점**: 같은 주기에서 와이퍼 출력을 먼저 계산한 뒤, 그 결과로 연속 작동 시간을 갱신합니다.

## 5. 기타

- **주기와 시간 처리**: `headLight.c`의 시간 누적이 +100 고정이므로 100ms 주기를 기준으로 합니다.
  - 행 간격이 100ms보다 크면 빠진 주기를 "아무 값도 들어오지 않은 주기"로 채웁니다. 로그에는 `~`로 표시되고, 그래서 미수신 고장과 수신 중단이 실제 시간대로 판정됩니다.
  - 시간이 증가하지 않는 행은 건너뜁니다.
  - 100ms의 배수가 아닌 간격은 경고만 하고 계속 진행합니다.
- **입력 검증**: 아래 경우는 stderr로 알립니다. 건너뛴 행이나 잘못된 값이 있으면 종료 코드는 2입니다.
  - 알 수 없는 enum 값(예: `GEAR_X`) → 그 칸은 미수신으로 처리
  - 필드 수가 12개가 아님, 512자를 넘는 줄 → 그 행을 건너뜀
  - int 범위를 넘는 숫자 → 포화시켜 범위 밖(센서 고장)으로 처리
- **시간 범위**: `time_ms`는 0~2147483647(약 24.8일)이어야 합니다. 범위를 벗어난 행은 값을 고쳐 쓰지 않고 건너뜁니다.
- **긴 공백 구간**: 입력 없이 6주기(600ms)가 지나면 모든 입력이 수신 중단 상태가 되어 출력이 더 이상 바뀌지 않습니다. 그래서 그 이후 구간은 로그에 `# A~B ms: 입력 없음 지속` 한 줄로 요약합니다. 이렇게 하지 않으면 시간이 크게 뛸 때 로그가 수 GB가 됩니다.
- **공용 헤더 정리**: `vehicle_control.h`에 include guard를 추가했고, `vehicle_control.h`와 `Wiper.c` 끝에 빠져 있던 줄바꿈을 넣었습니다. 로직은 바꾸지 않았습니다.
- **`vehicle_control.h`**: include guard가 없어서 한 파일에서 두 번 include하면 중복 정의 오류가 납니다.
- **입력 CSV 확장**: 사양서 3.1의 11개 항목 앞에 `time_ms` 열이 있습니다.
- **AI가 틀린 곳 (인수 조건 3번 자료)**:
  - 무엇이 틀렸나: 처음 작성한 main.c에서 `ReceivePeriodic(&x, ParseInt(text, &value), value, now)`처럼, 한 함수 호출의 인자 안에서 `value`를 쓰고 읽었습니다. C는 인자 평가 순서를 정하지 않으므로 값이 바뀌기 전의 `value`가 전달되었습니다.
  - 어떻게 알아챘나: 강우 센서 고장이 끝까지 풀리지 않았고, 도어도 잠기지 않았습니다.
  - 어떻게 고쳤나: 원문 문자열을 넘기고 함수 안에서 해석하도록 바꿨습니다.
