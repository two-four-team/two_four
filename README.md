# 가상 차량 차체 편의 기능 시뮬레이터

자동차의 **전조등 · 와이퍼 · 도어 잠금 · 계기판 경고**가 상황에 따라 어떻게 동작해야 하는지를 C로 구현한 프로젝트입니다.

실제 차량은 없습니다. 대신 "0.1초마다 차량 상태가 이랬다"를 적은 CSV 파일을 입력으로 주면, 프로그램이 그 순간마다 전조등을 켤지, 와이퍼를 어느 속도로 돌릴지, 문을 잠글지, 계기판에 어떤 경고를 띄울지를 계산해 텍스트 로그로 남깁니다. 입력 CSV를 바꿔 가며 출력이 어떻게 달라지는지 확인하는 것이 이 프로젝트의 사용 방법입니다.

## 프로젝트 배경

교육 과정의 팀 프로젝트입니다. 강사가 "고객" 역할을 맡아 **요구사항 사양서**(문서 번호 `VBC-SRS-001`, 버전 1.0)를 발행했고, 개발팀이 그 문서대로 소프트웨어를 만들어 요구사항별로 동작을 확인한 결과를 제시하는 과제입니다. 사양서 원본은 `Plan/` 폴더에 PDF로 들어 있지만, 이 README만 읽어도 프로젝트를 이해할 수 있도록 필요한 내용을 모두 옮겨 적었습니다.

사양서가 정한 것과 정하지 않은 것은 다음과 같습니다.

- **정한 것**: 어떤 입력에서 어떤 출력이 나와야 하는지(동작 규칙), 그리고 결과물은 입력을 바꿔 가며 출력 변화를 직접 보여 줄 수 있어야 한다는 것
- **정하지 않은 것**: 구현 언어, 프로그램 구조, 화면, 입력 방법, 시험 방법 → 팀이 결정

이 팀은 **C 언어**, **CSV 파일 입력**, **텍스트 로그 출력**을 선택했습니다.

사양서의 기능은 필수와 선택으로 나뉩니다.

| 구분 | 기능 | 이 프로젝트 |
| --- | --- | --- |
| 필수 | 조명, 와이퍼, 도어·잠금, 계기판 경고 | 구현함 |
| 선택 | 주행 (가속·브레이크 조작으로 차를 움직임) | 구현하지 않음. 속도·기어·시동을 CSV에 직접 적습니다 |
| 선택 | 팀이 직접 정의하는 추가 기능 | 구현하지 않음 |

### 요구사항 ID

사양서는 요구사항마다 ID를 붙였고, 소스 코드 주석과 이 README도 같은 ID를 씁니다. 코드에서 `/* L6 */` 같은 주석을 보면 아래 [동작 규칙](#동작-규칙)에서 해당 ID를 찾으면 됩니다.

| 접두어 | 분야 | ID |
| --- | --- | --- |
| C | 공통 규칙 (Common) | C1 ~ C5 |
| L | 조명 (Light) | L1 ~ L6 |
| W | 와이퍼 (Wiper) | W1 ~ W5 |
| D | 도어·잠금·경고 (Door) | D1 ~ D5 |

## 무엇을 입력받고 무엇을 내보내는가

### 입력 (차량 상태)

| 항목 | 유효한 값 | 설명 |
| --- | --- | --- |
| 속도 | 0 ~ 250 km/h | 방향이 없는 속력입니다. 후진 여부는 기어로 구분합니다 |
| 기어 | P / R / N / D | |
| 시동 | 켜짐 / 꺼짐 | |
| 조도 | 0 ~ 60000 lux | 주변 밝기. 조도 센서가 측정합니다 |
| 강우량 | 0 ~ 100 % | 비의 양. 강우 센서가 측정합니다 |
| 도어 4개 | 열림 / 닫힘 | 앞 왼쪽, 앞 오른쪽, 뒤 왼쪽, 뒤 오른쪽 |
| 조명 스위치 | AUTO / OFF / ON | 운전자가 조작 |
| 와이퍼 스위치 | OFF / AUTO / LOW / HIGH | 운전자가 조작 |

속도·기어·시동·조도·강우량은 **0.5초보다 짧은 간격으로 계속 들어오는 것**이 전제입니다. 값이 바뀌지 않아도 같은 값이 계속 들어와야 합니다. 값이 끊기면 고장으로 판단합니다([용어](#먼저-알아야-할-용어) 참고).

### 출력

| 항목 | 값 |
| --- | --- |
| 전조등 | 켜짐 / 꺼짐 |
| 조도 센서 고장 표시 | 고장 / 정상 |
| 와이퍼 | 정지 / 간헐 / 저속 / 고속 |
| 강우 센서 고장 표시 | 고장 / 정상 |
| 도어 잠금 | 잠김 / 풀림 |
| 계기판 경고 | 없음 / 주행 중 도어 열림 / 조도 센서 고장 / 강우 센서 고장 (한 번에 하나만) |

프로그램을 시작한 직후의 출력은 전조등 꺼짐, 와이퍼 정지, 도어 풀림, 경고 없음입니다. (C5)

## 먼저 알아야 할 용어

동작 규칙에 반복해서 나오는 표현입니다. 이 다섯 가지를 알면 규칙 표를 그대로 읽을 수 있습니다.

### N초 연속 (C1)

조건이 **끊기지 않고** N초 동안 성립한 상태입니다. 중간에 한 번이라도 조건이 깨지면 처음부터 다시 셉니다.

> 예: "조도 1000 lux 미만이 1초 연속이면 전조등을 켠다"에서, 0.9초 동안 어두웠다가 잠깐 밝아지면 시간은 0으로 돌아갑니다. 터널 입구의 그림자 같은 순간적인 변화에 전조등이 깜빡이지 않게 하기 위한 규칙입니다.

시간을 세는 조건은 규칙마다 다릅니다.

- 조도에 따른 시간(L2, L3)은 **시동이 켜져 있고, 조명 스위치가 AUTO이며, 조도 센서가 정상일 때만** 셉니다.
- 와이퍼 작동 시간(L6)은 **시동이 켜져 있고 와이퍼가 작동하는 동안** 셉니다. 조명 스위치 위치와는 관계없습니다.
- 우선순위가 더 높은 규칙이 전조등을 결정하고 있는 동안에도 시간은 계속 셉니다.

### 센서 고장 (C2)

조도 센서나 강우 센서의 값이 다음 중 하나에 해당하는 상태입니다.

- 값이 **0.5초 동안 들어오지 않음**
- 값이 **유효 범위 밖** (조도 0-60000 lux, 강우량 0-100%를 벗어남)

정상 값이 다시 들어오면 고장은 바로 풀립니다. 프로그램을 시작한 뒤 아직 값이 한 번도 들어오지 않았다면 시작 시점부터 0.5초를 셉니다.

### 차량 상태 수신 중단 (C4)

**속도·기어·시동 중 하나라도** 0.5초 동안 들어오지 않은 상태입니다. 차량 상태를 믿을 수 없으므로, 이때 조명과 와이퍼는 **시동이 꺼진 것으로 간주**합니다. 도어 잠금은 다르게 처리합니다(D1).

### 유효한 속도 (C3)

다음을 모두 만족할 때의 속도 값입니다.

- 속도·기어·시동이 각각 마지막으로 들어온 지 0.5초가 지나지 않음 (수신 중단이 아님)
- 속도가 0~250 km/h 범위 안

속도를 조건으로 쓰는 규칙(W3, D3, D4)은 유효한 속도일 때만 성립합니다. 즉 속도 값을 믿을 수 없으면 "속도가 0이다", "15 km/h 이상이다" 같은 조건은 모두 거짓으로 봅니다.

### 우선순위

여러 규칙이 동시에 성립하면 **앞에 적힌 규칙의 결과**를 따릅니다. 예를 들어 조명의 우선순위가 `L1 > L5 > L4 > …`이면, 시동이 꺼져 있을 때(L1)는 조명 스위치가 ON이어도(L4) 전조등은 꺼집니다.

## 동작 규칙

### 조명

우선순위: **L1 > L5 > L4 > L6 > L2 · L3** (표는 우선순위 순서로 정렬)

| ID | 조건 | 전조등 |
| --- | --- | --- |
| L1 | 시동이 꺼져 있음 (차량 상태 수신 중단 포함) | 꺼짐 |
| L5 | 조도 센서 고장 | 켜짐 |
| L4 | 조명 스위치 ON | 켜짐 |
| L4 | 조명 스위치 OFF | 꺼짐 |
| L6 | 스위치 AUTO, 와이퍼가 10초 연속 작동 | 켜짐 (와이퍼가 작동하는 동안 유지) |
| L2 | 스위치 AUTO, 조도 1000 lux 미만이 1초 연속 | 켜짐 |
| L3 | 스위치 AUTO, 조도 1500 lux 초과가 3초 연속 | 꺼짐 |
| — | 위 어느 것에도 해당하지 않음 | 직전 상태 유지 |

- L5: 밝기를 알 수 없으면 안전한 쪽인 "켜짐"을 선택합니다. 조도 센서 고장 **표시**는 시동이 꺼져 있어도 합니다.
- L6: "와이퍼 작동"은 와이퍼 단계가 정지가 아닌 상태를 말합니다. 비가 계속 오면 밝기와 무관하게 전조등을 켭니다.
- L2·L3: 켜는 기준(1000)과 끄는 기준(1500)이 다릅니다. 조도가 1000~1500 사이이거나 아직 시간이 차지 않았으면 직전 상태를 유지하므로, 경계 근처에서 전조등이 켜졌다 꺼졌다 반복하지 않습니다.

### 와이퍼

우선순위: **W1 > W4 > W5 > W2 · W3**

| ID | 조건 | 와이퍼 |
| --- | --- | --- |
| W1 | 시동이 꺼져 있음 (차량 상태 수신 중단 포함) | 정지 |
| W4 | 와이퍼 스위치 OFF | 정지 |
| W4 | 와이퍼 스위치 LOW | 저속 |
| W4 | 와이퍼 스위치 HIGH | 고속 |
| W5 | 스위치 AUTO, 강우 센서 고장 | 간헐 |
| W2 | 스위치 AUTO, 강우량에 따라 | 아래 표 |
| W3 | 스위치 AUTO, 유효한 속도가 0 | W2 결과를 한 단계 낮춤 |

AUTO일 때 강우량별 와이퍼 단계(W2)와, 정차 중일 때 낮춘 결과(W3):

| 강우량 | 주행 중 (W2) | 정차 중, 속도 0 (W3) |
| --- | --- | --- |
| 10% 미만 | 정지 | 정지 |
| 10% 이상 40% 미만 | 간헐 | 정지 |
| 40% 이상 70% 미만 | 저속 | 간헐 |
| 70% 이상 | 고속 | 저속 |

- W5: 강우 센서 고장 **표시**는 시동과 와이퍼 스위치 위치에 관계없이 합니다. W5가 W3보다 우선하므로, 센서 고장일 때는 정차 중이어도 간헐에서 더 낮추지 않습니다.
- W3: 속도 값을 믿을 수 없으면(유효한 속도가 아니면) 낮추지 않습니다.

### 도어 잠금

D1 → D2 → D3 순서로 판단하고, 먼저 해당하는 규칙을 따릅니다.

| ID | 조건 | 도어 잠금 |
| --- | --- | --- |
| D1 | 차량 상태 수신 중단 | 직전 상태 유지 |
| D2 | 시동이 꺼져 있거나 기어가 P | 풀림 |
| D3 | 유효한 속도가 15 km/h 이상 | 잠김 |
| — | 위 어느 것에도 해당하지 않음 | 직전 상태 유지 |

- D1: 차량 상태를 알 수 없을 때 문을 함부로 잠그거나 풀지 않습니다. 조명·와이퍼가 수신 중단을 "시동 꺼짐"으로 보는 것과 다른 점입니다.
- D3: 한 번 잠기면 속도가 15 km/h 아래로 내려가도 잠긴 상태가 유지되고, 기어를 P에 넣거나 시동을 꺼야 풀립니다.

### 계기판 경고

| ID | 내용 |
| --- | --- |
| D4 | 유효한 속도가 0보다 크고 문이 하나라도 열려 있으면 "주행 중 도어 열림" |
| D5 | 경고는 한 번에 하나만 표시합니다. 여러 개가 동시에 해당하면 **주행 중 도어 열림 > 조도 센서 고장 > 강우 센서 고장** 순으로 하나를 고르고, 해당하는 것이 없으면 표시하지 않습니다 |

## 빌드와 실행

모든 명령은 **프로젝트 루트**에서 실행합니다. C 컴파일러만 있으면 되고 외부 라이브러리는 필요 없습니다.

### 한 번에 빌드하고 실행하기 (Linux / macOS / WSL)

```bash
./run.sh [입력 csv] [출력 로그]
```

아래 gcc 명령으로 빌드한 뒤 바로 실행합니다. 인자는 `vehicle_sim`에 그대로 전달되고, 생략하면 `output/`에 새 로그 파일이 생깁니다. 실행 권한이 없다면 `bash run.sh`로 실행하세요.

### Linux / macOS (gcc)

```bash
gcc -std=c99 -Wall -Wextra -I Common -o vehicle_sim \
    Common/main.c HeadLight/headLight.c Wiper/Wiper.c Door/Door.c \
    sensor/sensor.c "Dashboard Warning/ClusterWarning.c"
```

### Windows (Visual Studio 개발자 명령 프롬프트)

```bat
cl /nologo /W3 /utf-8 /I Common /Fe:vehicle_sim.exe Common\main.c HeadLight\headLight.c ^
   Wiper\Wiper.c Door\Door.c sensor\sensor.c "Dashboard Warning\ClusterWarning.c"
```

- `main.c`는 UTF-8(BOM 포함)로 저장되어 있습니다. 편집기에서 다시 저장할 때 BOM을 지우면 한글이 깨질 수 있습니다.
- Visual Studio 프로젝트로 빌드한다면 작업 디렉터리를 프로젝트 루트로 설정하거나, 입력/출력 경로를 인자로 넘기세요.

### 실행

```bash
./vehicle_sim [입력 csv] [출력 로그]
```

두 인자 모두 생략할 수 있습니다.

| 인자 | 생략했을 때 | 설명 |
| --- | --- | --- |
| 입력 csv | `input/input.csv` | 차량 상태 시나리오 |
| 출력 로그 | `output/simulation_log_YYYYMMDD_HHMMSS.txt` | 실행 시각으로 새 파일을 만듭니다. 같은 초에 다시 실행하면 `_2`, `_3` …이 붙습니다. 경로를 직접 주면 그 파일에 덮어씁니다 |

실행이 끝나면 요약이 콘솔에 출력됩니다.

```
시뮬레이션 완료: 833행 처리, 보간 주기 0, 건너뛴 행 0, 잘못된 값 0, 로그: output/simulation_log_20261008_111248.txt
```

| 종료 코드 | 의미 |
| --- | --- |
| `0` | 정상 |
| `1` | 파일 오류 (입력/출력 파일을 열 수 없음, 쓰기 실패) |
| `2` | 입력에 건너뛴 행이나 해석할 수 없는 값이 있음 (로그는 생성됨) |

## 입력 CSV 작성법

첫 줄은 헤더이고, 그다음부터 **한 행이 한 주기(0.1초)** 의 차량 상태입니다.

```csv
time_ms,speed,gear,engineState,illuminance,rainAmount,doorFL,doorFR,doorRL,doorRR,lightSwitch,wiperSwitch
0,0,GEAR_P,ENGINE_ON,20000,0,DOOR_CLOSED,DOOR_CLOSED,DOOR_CLOSED,DOOR_CLOSED,LIGHT_AUTO,WIPER_SWITCH_AUTO
100,0,GEAR_P,ENGINE_ON,20000,0,DOOR_CLOSED,DOOR_CLOSED,DOOR_CLOSED,DOOR_CLOSED,LIGHT_AUTO,WIPER_SWITCH_AUTO
```

| 열 | 적을 수 있는 값 | 의미 |
| --- | --- | --- |
| `time_ms` | 0 이상의 정수 | 시각(밀리초). 100씩 증가해야 합니다 |
| `speed` | 정수 | 속도(km/h). 0~250이 유효 |
| `gear` | `GEAR_P` `GEAR_R` `GEAR_N` `GEAR_D` | 기어 |
| `engineState` | `ENGINE_OFF` `ENGINE_ON` | 시동 |
| `illuminance` | 정수 | 조도(lux). 0~60000이 유효 |
| `rainAmount` | 정수 | 강우량(%). 0~100이 유효 |
| `doorFL` `doorFR` `doorRL` `doorRR` | `DOOR_CLOSED` `DOOR_OPEN` | 앞 왼쪽, 앞 오른쪽, 뒤 왼쪽, 뒤 오른쪽 도어 |
| `lightSwitch` | `LIGHT_AUTO` `LIGHT_OFF` `LIGHT_ON` | 조명 스위치 |
| `wiperSwitch` | `WIPER_SWITCH_OFF` `WIPER_SWITCH_AUTO` `WIPER_SWITCH_LOW` `WIPER_SWITCH_HIGH` | 와이퍼 스위치 |

### 고장 상황을 만드는 방법

- **범위 밖 값을 적는다**: `illuminance`에 `-1`이나 `70000`을 적으면 조도 센서 고장이 됩니다.
- **칸을 비운다**: 빈 칸은 "이번 주기에 값이 들어오지 않았다"는 뜻입니다.
  - 속도·기어·시동·조도·강우량 칸을 5행(0.5초) 연속으로 비우면 수신 중단 또는 센서 고장이 됩니다.
  - 도어·스위치 칸은 비워도 고장이 아니며, 직전 값이 유지됩니다.
- **행을 건너뛴다**: 행 사이 간격이 100ms보다 크면, 빠진 주기는 모든 값이 들어오지 않은 주기로 채워서 처리합니다.

### 잘못된 입력의 처리

| 상황 | 처리 |
| --- | --- |
| 해석할 수 없는 값 (오타 등) | 그 칸만 "값이 들어오지 않음"으로 처리 |
| 필드 수가 12개가 아닌 행 | 행 전체를 건너뜀 |
| `time_ms`가 없거나 직전 행보다 크지 않은 행 | 행 전체를 건너뜀 |
| 간격이 100ms의 배수가 아닌 행 | 처리하되 경고 출력 |

어느 경우든 표준 오류로 몇 번째 행이 왜 문제인지 출력합니다.

## 출력 로그 읽는 법

주기마다 한 줄씩, 그 시점의 출력 6가지를 기록합니다. 아래는 저장소에 포함된 `input/input.csv`를 실행한 로그의 앞부분입니다.

```
# 차체 편의 기능 시뮬레이션 로그 (VBC-SRS-001 v1.0, 3.2 출력)
# 실행 시각: 2026-10-08 11:12:48
# 입력: input/input.csv
# 주기: 100 ms, 수신 중단 판정: 500 ms
#
time_ms  | 전조등 | 조도 센서 | 와이퍼 | 강우 센서 | 도어 잠금 | 계기판 경고
---------+--------+-----------+--------+-----------+-----------+------------------
0        | 꺼짐   | 정상      | 정지   | 정상      | 풀림      | 없음
...
400      | 꺼짐   | 정상      | 정지   | 정상      | 풀림      | 없음
500*     | 꺼짐   | 고장      | 정지   | 고장      | 풀림      | 조도 센서 고장
600      | 꺼짐   | 고장      | 정지   | 고장      | 풀림      | 조도 센서 고장
700*     | 꺼짐   | 정상      | 정지   | 정상      | 풀림      | 없음
```

| 표시 | 의미 |
| --- | --- |
| `*` | 직전 행과 출력이 달라진 행. 이 표시만 찾아 읽으면 변화 시점을 빠르게 볼 수 있습니다 |
| `~` | 입력 CSV에 행이 없어 빈 주기로 채운 행 |

이 예시는 다음과 같이 읽습니다.

- **0 ~ 400ms**: 입력 파일의 이 구간은 조도·강우량 칸이 비어 있습니다. 아직 0.5초가 지나지 않았으므로 센서는 정상으로 봅니다.
- **500ms**: 시작 후 0.5초 동안 값이 들어오지 않아 두 센서가 모두 고장이 됩니다(C2). 경고는 하나만 표시하므로 우선순위가 높은 "조도 센서 고장"이 뜹니다(D5). 조도 센서 고장이면 전조등을 켜야 하지만(L5), 시동이 꺼진 상태가 우선이라(L1) 꺼져 있습니다.
- **700ms**: 입력 파일의 이 행부터 정상 값이 들어오므로 고장이 풀리고 경고가 사라집니다.

입력이 오래 끊겨 출력이 더 바뀌지 않는 구간은 행을 일일이 쓰지 않고 한 줄로 요약합니다.

## 코드 구조

제어 모듈의 함수는 모두 **내부 상태가 없는 순수 함수**입니다. 같은 입력을 주면 항상 같은 결과가 나오므로 함수 하나씩 따로 테스트할 수 있습니다. 시간의 흐름과 "직전 상태"처럼 기억이 필요한 부분은 `main.c`가 맡습니다.

| 담당 | 하는 일 |
| --- | --- |
| `main.c` | CSV 읽기, 0.5초 미수신 판정, 유효한 속도 판정, 연속 시간을 셀지 말지 결정, 직전 상태 보관(전조등, 도어 잠금, 연속 시간), 로그 쓰기 |
| 모듈 함수 | 전달받은 값만으로 출력 결정 |

### 한 주기의 처리 순서

1. CSV 한 행에서 입력을 받는다
2. 차량 상태 수신 중단 여부를 판정하고(C4), 유효한 속도를 구한다(C3)
3. 조도·강우 센서의 고장 여부를 판정한다(C2)
4. 와이퍼 단계를 정하고, 와이퍼 연속 작동 시간을 갱신한다
5. 조도 연속 시간을 갱신하고, 전조등을 정한다
6. 도어 잠금을 정한다
7. 주행 중 도어 열림을 판단하고, 계기판 경고를 고른다

와이퍼를 전조등보다 먼저 계산하는 이유는 "와이퍼가 10초 연속 작동하면 전조등을 켠다"(L6)가 와이퍼 결과에 의존하기 때문입니다.

### 모듈 함수

| 함수 | 파일 | 역할 | 관련 규칙 |
| --- | --- | --- | --- |
| `ControlHeadLight` | `HeadLight/headLight.c` | 전조등 켜짐/꺼짐 결정 | L1 ~ L6 |
| `UpdateLowIlluminanceTime` | `HeadLight/headLight.c` | 조도 1000 lux 미만이 이어진 시간 | L2 |
| `UpdateHighIlluminanceTime` | `HeadLight/headLight.c` | 조도 1500 lux 초과가 이어진 시간 | L3 |
| `UpdateWiperActiveTime` | `HeadLight/headLight.c` | 와이퍼가 연속으로 작동한 시간 | L6 |
| `ControlWiper` | `Wiper/Wiper.c` | 와이퍼 단계 결정 | W1 ~ W5 |
| `ControlDoorLock` | `Door/Door.c` | 도어 잠금/해제 결정 | D1 ~ D3 |
| `CheckDoorOpenWhileDriving` | `Door/Door.c` | 주행 중 도어 열림 판단 | D4 |
| `DetermineClusterWarning` | `Dashboard Warning/ClusterWarning.c` | 표시할 경고 하나 선택 | D5 |
| `CheckLightSensorFault` | `sensor/sensor.c` | 조도 값이 유효 범위 안인지 검사 | C2 |
| `CheckRainSensorFault` | `sensor/sensor.c` | 강우량 값이 유효 범위 안인지 검사 | C2 |
| `CheckVehicleStateRx` | `sensor/sensor.c` | 속도·기어·시동 중 하나라도 끊겼는지 종합 | C4 |

연속 시간 함수 세 개는 호출될 때마다 조건이 맞으면 현재 값에 100(ms)을 더해 돌려주고, 맞지 않으면 0을 돌려줍니다. 0.1초마다 한 번씩 호출된다는 전제입니다.

## 알려진 제약

- 주기는 100ms로 고정되어 있습니다. 행 간격이 100ms의 배수가 아니어도 연속 시간은 주기당 100ms로 셉니다.
- 0.5초 미수신 판정, 유효한 속도 판정, 연속 시간을 셀지 결정하는 로직은 현재 모듈이 아니라 `main.c`에 있습니다. 나중에 모듈로 옮길 수 있도록 `Sim`으로 시작하는 함수로 분리해 두었습니다.
- 와이퍼를 한 단계 낮추는 처리(W3)는 `WiperState` enum이 `정지 < 간헐 < 저속 < 고속` 순서로 정의되어 있다는 전제에 의존합니다. enum 순서를 바꾸면 함께 고쳐야 합니다.
- CSV 한 줄은 최대 511자이며, 이를 넘는 줄은 건너뜁니다.
